# 知行AI遗漏需求补充与验收清单

本文是对《知行AI项目总览》的补充。下列细节来自历史讨论，不代表当前代码已经实现，也不将旧原型误认为当前生产版本。

## 一、历史聊天前端功能

此前讨论过一个名为 `zhixing-ai.html` 的纯前端聊天版本，但其具体归属仓库和当前部署状态尚未核实。旧方案曾包括：
- 用户手动填写 API Key、手动清除记录；曾讨论 DeepSeek 与小米 MiMo（`mimo.mi.com`）。
- 对话记录 JSON 导入/导出、文件/图片上传、搜索过程展示。
- 缓存统计必须基于真实字段；拉丁字母和数字使用 JetBrains Mono；支持 Shift+Enter 换行。
- 该特定历史版本曾偏好不提供浅色模式。不要将此要求自动套用到普通计算器或其他页面。

纯前端自带密钥模式与当前服务端代理模式不同。当前实现必须以代码和部署为准；不得为了兼容旧方案将服务端密钥放进公开前端。

## 二、交互要求遗漏项

- 附件入口曾要求整合为一个图标入口，而不是将图片、相机、文件做成三个冗长的文字按钮。
- 思考状态只保留流动高光效果；发生错误时停止动画。流式输出应正确处理取消、断流、超时和重复提交。
- 结果优先展示重点，次要内容默认折叠，但不能把关键结果藏起来。
- 必须真实验证行内/块级 LaTeX、分数、根式、上下标、长公式换行和手机端溢出。
- 字体要求按具体页面区分：历史上曾要求后台使用 OPPO Sans，也曾要求 AI 计算器沿用知行计算器字体；不能不加区分替换整个站点字体。字体加载失败需有回退，不得无限停留在加载状态。

## 三、后台与模型服务的详细故障

历史报告过：模型列表能读取但无法选择；模型显示名称与实际 ID 不一致（例如 `gpt6-luna` 与 `astra`）；token 用量和余额不可查看；模型服务请求失败。应分项检查上游当前文档、模型列表格式、请求中的实际 model ID、用量和余额接口、权限及错误处理。接口不支持余额时应明确说明，不能显示虚构的 0。

提示词应由后端安全管理，知行AI学习版与知行计算器AI版可共享管理基础设施，但提示词、产品上下文和权限需隔离。AI 计算器要自动携带当前页面、输入与计算结果，不要求用户再复制粘贴。

## 四、补充回归测试

| 范围 | 验收内容 |
|---|---|
| 聊天 | 连续追问、历史记录、刷新恢复、重复发送、失败后清理思考状态 |
| 文件/图片 | 支持类型、超限、上游不支持、失败反馈、敏感内容不进日志 |
| 模型 | 获取列表、切换模型、实际调用、流式输出、用量/余额真实状态 |
| 后台 | 管理员登录、普通账号管理、提示词和配置保存、产品切换与权限隔离 |
| 手机 | 弹窗不被键盘遮挡、控件不挤压、无横向溢出、公式可读、文字不竖排 |
| 云存储 | 云端记录合入最近对话、会话 ID 去重、刷新和多设备同步 |

每项须注明通过、失败或未执行，并保留可核验的提交、工作流或实际测试证据。

## 五、边界

这些是历史遗漏点及验收要求，不表示已部署或修复。旧页面归属、实际上传能力、字体加载行为和当前上游用量接口仍需从现有代码与线上配置确认。
